# Forward+ renderer evaluation

> **STATUS: ADOPTED:** The user approved Forward+ after a live two-client playtest. The balanced profile is the visual bake-off baseline; lean remains the low-spec profile and showcase remains opt-in evidence.

## Adopted decision

This record evaluated whether native desktop SKOOSH should use Godot Forward+
before the visual-direction bake-off. The user adopted Forward+; the evaluation
steps below are retained as decision evidence rather than current work.

## User playtest

The default project profile is **balanced**:

```bash
./tools/run_multiplayer_demo.sh
```

Optional comparisons:

```bash
SKOOSH_RENDERER_PROFILE=lean ./tools/run_multiplayer_demo.sh
SKOOSH_RENDERER_PROFILE=showcase ./tools/run_multiplayer_demo.sh
```

`lean` retains Forward+, clustered team lighting, decals, ordinary depth fog, and FXAA. `balanced` adds SSAO and restrained global/local volumetric fog. `showcase` additionally enables TAA, SSIL, SSR, and SDFGI. Stop the server and both clients together with Ctrl-C in the launching terminal.

## Correct off-screen comparison path

Xvfb cannot provide Vulkan WSI/DRI3 presentation. Launching Forward+ under Xvfb correctly failed because no device exposed both graphics and presentation queues. Godot's headless display uses the dummy renderer and cannot produce representative 3D captures.

`tools/capture_visual_qa_private_wayland.sh` starts a private headless Weston compositor for each rendered process. This gives Vulkan or OpenGL a real GPU-backed Wayland presentation queue without opening windows on the user's desktop. Dedicated servers still use Godot's headless display.

The first Compatibility contact sheet used Xvfb/llvmpipe and was therefore not a fair performance or renderer comparison against Forward+/RADV. The final Compatibility profile was rerun through the same Weston/GPU path. Logs explicitly identify the active method and driver; the harness always passes `--rendering-method` even when other rendering flags are supplied.

Weston itself was not a material cost. The operational issues found were cold Vulkan pipeline startup and failed runs leaving descendant processes alive. The visual-QA cleanup now terminates full process trees, and the connection allowance accommodates cold Forward+ compilation.

Weston is only required for automated off-screen Forward+ capture. Normal desktop playtesting does not require the wrapper.

## Capability profiles

### Lean — provisional low-spec profile

- Forward+ / Vulkan.
- TAA, SSAO, SSIL, SSR, SDFGI, and volumetric fog disabled.
- FXAA enabled.
- Team-tinted projected decals.
- Eight unshadowed local base lights, in addition to existing gameplay lights.
- Existing directional light, depth fog, sky, PBR materials, and authored assets.

This isolates the value of Forward+'s modern rendering path, decals, and clustered-light headroom without depending on expensive screen-space or GI features.

### Balanced — recommended default

Everything in lean, plus:

- SSAO for contact grounding.
- Restrained global volumetric fog.
- Local team-tinted fog volumes around bases.

This produced a clear atmosphere/readability change without requiring SSR, SSIL, SDFGI, or TAA.

### Showcase — opt-in ceiling demonstration

Everything in balanced, plus:

- SSIL.
- Screen-space reflections.
- SDFGI with sky light and occlusion.
- TAA.

The current runway art does not give these expensive features enough reflective, indirect-light, or fine-motion content to justify enabling them by default. Their screenshots were only subtly different from balanced.

## Example content

## Measurements

Test conditions:

- Godot 4.4.1.
- 1280×720 live multiplayer visual-QA route.
- Private Weston headless compositor.
- AMD Radeon RX 7900 XT using RADV for Forward+ and radeonsi for Compatibility.
- VSync and frame cap disabled for the profiled rendered client.
- First three one-second samples discarded.
- Values are Godot project-frame intervals, not isolated GPU timestamps.

| Profile | Median frame | p90 | p95 | Worst sampled |
|---|---:|---:|---:|---:|
| Compatibility baseline, GPU-backed | 2.10 ms | 2.22 ms | 2.26 ms | 2.39 ms |
| Forward+ lean | 0.97 ms | 1.06 ms | 1.07 ms | 1.30 ms |
| Forward+ balanced | 1.05 ms | 1.09 ms | 1.17 ms | 1.21 ms |
| Forward+ showcase | 1.07 ms | 1.12 ms | 1.15 ms | 1.38 ms |

These numbers prove that Weston is not the bottleneck and that Forward+ does not impose a visible frame-time penalty on this machine. They do **not** establish a low-end requirement. The GPU is far above any plausible minimum specification, and relative costs will not scale uniformly to integrated graphics.

## Min-spec gate

Forward+ requires a supported modern desktop graphics API. Feature scaling cannot recover a machine that cannot initialize the renderer. SKOOSH does not yet state a minimum GPU, and this host has no integrated or low-end secondary GPU.

Before publishing a firm hardware requirement, run the lean and balanced profiles at 1080p on at least one representative integrated GPU and one older discrete GPU. A reasonable provisional target class is Intel UHD 620 / AMD Vega 8 or better, but that is a test target—not a currently verified requirement.

If supporting pre-Vulkan/OpenGL-only desktop hardware is a product requirement, the project should remain on Compatibility or ship and maintain a genuinely separate build. Loading Forward+-only resources such as `FogMaterial` under Compatibility produces explicit unsupported-renderer errors, so a silent one-scene desktop fallback is not a clean hedge.

## TAA and Godot version

TAA is disabled in lean and balanced. Fast first-person camera motion makes ghosting and temporal instability particularly relevant, and the current visuals do not justify its default cost.

Godot 4.5 adds SMAA, which may be a better native antialiasing option. That should be a separate engine-upgrade qualification rather than silently changing engine and renderer during this experiment. Godot 4.4's FXAA is used for the current lean/balanced comparison.

## Adopted policy

Forward+ with **balanced** is the bake-off baseline:

- Permit decals, clustered lights, SSAO, and restrained volumetric fog.
- Keep TAA, SSR, SSIL, and SDFGI disabled by default.
- Let a bake-off candidate enable an expensive feature only when its direction visibly benefits and its brief records the fallback/cost.
- Retain lean as the low-spec feature profile.
- Keep private-Weston contact sheets as regression evidence, not as min-spec performance proof.
- Record low-end hardware qualification as a release gate rather than pretending the 7900 XT answered it.
